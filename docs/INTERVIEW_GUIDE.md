# 车载平衡滚球项目：技术复盘与面试准备

这份文档不是项目宣传稿，而是用于回答面试追问的技术底稿。目标是：你不仅能说“我做了一个滚球小车”，还能够解释系统为什么这样分层、各控制环如何工作、真实机械问题如何暴露、代码如何保证实时性和安全性，以及现有方案还有什么缺陷。

---

## 1. 先学会用一句话讲清项目

### 1.1 30秒版本

> 我基于TI MSPM0G3507实现了一套车载平衡滚球系统。小车用八路灰度和双编码器完成巡线，MaixCAM通过UART输出球位和球速，42型步进电机通过曲柄摆杆调节钢球。软件采用200 Hz巡线PD、40 Hz双轮PI和100 Hz滚球控制，并针对视觉延迟、静摩擦、开环步进丢步和正负方向机械不对称加入了状态机、前馈、软行程和故障保护。

### 1.2 2分钟版本

> 这个系统实际上有三个相互耦合的动态对象：车轮、车体和摆杆上的球。底盘部分使用八路灰度计算黑线质心误差，由200 Hz外环PD产生左右轮目标速度，再由40 Hz编码器PI跟踪。滚球部分由MaixCAM输出球位和球速，MSPM0以100 Hz运行控制器，把期望球加速度换算成摆杆右端的等效高度，再转换为42型步进电机脉冲。
>
> 最难的问题不是写一个普通PID，而是处理真实系统的非理想因素。比如任务3从+5 cm向-5 cm运动时，速度D项会在离目标还很远时压过限幅后的P项，导致摆杆提前反向，振荡逐次放大。最终我把负向控制分成远段和最后25 mm制动段：远段D项只能卸载到水平，不能产生反向加速度；进入近段才允许真正反制，并降低捕获阶段的加速度、行程和静摩擦补偿上限。
>
> 另外，任务3定点往返和任务4—6行车居中采用两套独立控制器。任务4还加入1.2 s车轮速度斜坡和短时反向摆杆前馈，JY61P角度只作为限幅前馈，失效时视觉闭环仍能运行。整个系统使用无RTOS的多周期协作调度，UART中断只收字节，协议解析和控制放在主循环中。

## 2. 你从这个项目真正学到了什么

### 2.1 控制系统不是“套PID公式”

你应该理解：实际控制器往往是“反馈控制＋状态机＋约束＋保护”的组合。

本项目中的典型例子：

- 巡线不是单一PD，还包括五次多数滤波、外侧传感器快速回拉、分级降速、转向变化率限制和失线恢复。
- 轮速不是纯PI，还包括速度前馈、输出上下限和条件积分抗饱和。
- 任务3不是单一位置PID，而是剩余距离速度规划、位置/速度反馈、边界预测、静摩擦探测、捕获阶段限幅和方向不对称处理。
- 任务4不是只把目标设为0，而是车轮缓加速、起步前馈、姿态前馈和独立视觉保持环共同工作。

面试时不要说“我用了PID所以稳定了”。更好的表达是：

> PID/PD只负责局部连续控制；任务切换、视觉失效、静摩擦、边界保护和执行器约束由状态机及限幅逻辑处理。

### 2.2 学会把需求拆成多个时间尺度

代码中存在以下时间尺度：

| 功能 | 周期/频率 | 原因 |
|---|---:|---|
| SysTick时基 | 1 ms / 1 kHz | 按键、灰度采样、软件计时 |
| 灰度巡线外环 | 5 ms / 200 Hz | 对弯道误差快速响应 |
| 轮速PI | 25 ms / 40 Hz | 在足够编码器边沿数与响应速度间折中 |
| 任务3滚球控制 | 10 ms / 100 Hz | 跟随视觉帧并保持控制连续性 |
| 任务4—6保持控制 | 10 ms / 100 Hz | 与球位/速度反馈匹配 |
| OLED刷新 | 80 ms / 12.5 Hz | 避免显示操作占用过多时间 |
| STEP调度中断 | 50 μs / 20 kHz | 用相位累加器合成可变步频 |

关键认识：不是所有功能都应该塞进1 ms中断。高频中断只做确定、短小的工作；解析协议、状态机和显示放在主循环中。

### 2.3 学会面对真实机械系统的不对称

理论模型通常假设左右方向一致，但实物可能存在：

- 曲柄几何在不同角度的增益不同；
- 摆杆和球槽摩擦不均匀；
- 钢球向左、向右的静摩擦阈值不同；
- 步进电机正反向间隙和负载不同；
- 视觉速度估计在折返时噪声更大。

因此代码分别学习正负方向的起动补偿，并对 `+50 mm → -50 mm` 路径单独设置加速度、命令、探测和斜率限制。这不是“参数写乱了”，而是通过实验承认对象不对称。

### 2.4 学会区分“软件正确”和“硬件验证”

你应该能明确说出以下层次：

1. 代码能编译，不等于引脚正确。
2. SysConfig能生成，不等于外设接线正确。
3. UART有数据，不等于坐标符号和单位正确。
4. 电机能转，不等于闭环方向正确。
5. 单次成功，不等于重复性可靠。

项目中多次出现的“前几次正常、后面失稳”，很可能涉及开环步进累计丢步、人工零点变化、机械摩擦变化或电源/驱动设置变化，不能只靠继续调PID掩盖。

## 3. 系统架构必须讲明白

### 3.1 感知层

- 八路灰度传感器：获得黑线横向位置和横向标志线。
- 双轮编码器：获得左右轮速度和累计里程。
- MaixCAM Pro：获得钢球位置、速度、置信度、检测状态和测量年龄。
- JY61P：获得车辆/摆杆安装方向上的姿态角。
- 按键：任务选择、确认、启动/暂停和急停。

### 3.2 控制层

- 巡线外环：灰度误差 → 左右轮目标速度。
- 轮速内环：编码器速度 → PWM占空比。
- 任务3控制器：中心 → +50 mm → -50 mm。
- 任务4—6控制器：行驶过程中保持中心或锁存指定位置。
- 任务状态机：SELECT、ARMED、RUNNING、BRAKING、COMPLETE、FAULT、ESTOP等。

### 3.3 执行层

- TB6612FNG驱动左右直流电机。
- D36A接收STEP/DIR/EN，驱动42型步进电机和曲柄摆杆。
- OLED和蜂鸣器提供状态与故障信息。

### 3.4 为什么分层

分层的价值不只是代码整洁，而是让每个问题有明确归属：

- 引脚和寄存器属于BSP/SysConfig。
- 协议帧、CRC和超时属于protocol。
- PD、PI、前馈和轨迹属于control。
- 任务选择和故障转移属于app。

面试官如果问“为什么不用一个大 `main.c`”，可以回答：

> 分层降低了硬件变化和控制算法变化的耦合。例如更换视觉模块时只需要保持 `VisionBallObservation` 接口；修改球位控制器时不需要碰UART中断和GPIO。

## 4. 八路灰度巡线：你必须会推导

### 4.1 质心误差

八个传感器从左到右赋值为1000、2000……8000，激活通道的平均值减去中心4500：

```text
error = sum(active_index × 1000) / active_count - 4500
```

因此：

- D4、D5同时激活时误差为0；
- 线偏向右侧传感器时误差为正；
- 横线激活通道较多，代码以 `activeCount >= 4` 判定marker。

### 4.2 输入滤波

GPIO在1 kHz下采样，保存最近5个样本，对每一位做多数表决。这能去掉单次毛刺，但不会引入很大的延迟。

中心附近再使用轻度一阶滤波：

```text
filtered = (old + 3 × new) / 4
```

但大误差或误差过零时直接采用新值，避免为了平滑而错过弯道。

### 4.3 外侧快速回拉

当D1/D2或D7/D8单独看到线时，代码绕过普通滤波和转向斜率限制，直接给出强差速。内侧轮仍保持正转，不做原地旋转，目的是快速回线同时减少姿态突变。

### 4.4 巡线PD

```text
steering = clamp(Kp × error + Kd × Δerror)
left_target  = base + steering
right_target = base - steering
```

当前参数采用整数比例：

- `Kp = 1/120`
- `Kd = 1/180`
- D项限幅±8
- 总转向限幅±30
- 每5 ms转向变化最多10

误差越大，基础速度从直道速度逐级降到弯道和边缘速度，避免“高速时只增加转向，却不降低总能量”。

### 4.5 失线策略

短时失线时沿用最近转向方向，最多保持约250 ms；超过窗口进入线路故障。这个方案适合胶带短缺口，但如果赛道存在较长空白，应该改用更明确的搜索状态机。

## 5. 双轮速度闭环：为什么是前馈＋PI

### 5.1 串级结构

外层巡线PD决定“应该左右轮差多少”，内层轮速PI负责“实际轮速跟上目标”。这样可以把路径误差和左右电机个体差异分开整定。

### 5.2 速度计算

编码器边沿在GPIO中断中累计。控制器每5 ms取得增量，但累计5次，即25 ms后更新一次PI；再把25 ms边沿数归一到50 ms参考窗口并除以每个速度单位对应的4个边沿。

面试官可能问：为什么不每5 ms更新PI？

> 低速时5 ms内边沿太少，量化噪声很大。25 ms窗口能得到更稳定的测速，同时40 Hz对车轮机械惯性仍足够快。

### 5.3 前馈＋PI公式

```text
PWM = FF(target) + Kp × (target - measured) + integral / KiDiv
```

当前输出限制为4%～40%。前馈提供大部分基础驱动力，PI只修正负载、轮胎和电池变化，这比让积分项从0慢慢“顶上去”响应更快。

### 5.4 抗积分饱和

只有在输出未饱和，或者误差方向有助于脱离饱和时，才接受新的积分值。这叫条件积分 anti-windup。

如果没有它，急弯或堵转时积分会积累很大，恢复后仍持续输出，造成明显冲击。

## 6. 视觉通信：不仅是“串口收到坐标”

### 6.1 物理与数据链路

- UART1，115200-8-N-1，3.3 V TTL。
- 27字节固定帧。
- 帧头 `0xA5 0x5A`。
- 版本和消息类型字段。
- 16位序号。
- 18字节载荷。
- CRC16-CCITT-FALSE。

载荷包含球位、球速、检测框、目标数量、标志位和视觉端测量年龄。

### 6.2 为什么需要序号和年龄

UART“有数据”不代表数据是新的。序号用于发现重复帧和估算丢帧；`sourceAgeMs`用于区分实时测量与视觉端预测/缓存结果。

### 6.3 接收并发模型

UART RX中断只做两件事：读取硬件FIFO、放入256字节单生产者/单消费者环形缓冲区。主循环再逐字节解析协议。

好处：

- ISR短，避免阻塞步进脉冲和编码器中断；
- 协议重同步和CRC计算不会拉长中断时间；
- 可以统计缓冲区溢出。

主循环读取首尾指针时短暂关中断，避免ISR同时修改共享状态。

### 6.4 错帧恢复

如果固定帧校验失败，解析器不会简单清空所有字节，而是在已收帧内部寻找下一组帧头；最后一个字节如果恰好是 `0xA5`，会保留作为下一帧开头。这减少了随机丢字节后的恢复时间。

### 6.5 多级有效性

协议层检查：

- 格式、版本、长度、CRC；
- `valid`范围；
- 置信度不超过100；
- 球位不超过±150 mm；
- 球速不超过±3000 mm/s；
- 数据年龄；
- 是否已完成毫米标定。

超过120 ms没有新接收，观测会被标为陈旧。

### 6.6 代码审查时要诚实指出的一点

`VisionProtocol`已经计算了 `controlUsable`，包含60%的置信度门槛；但当前任务层主要依据 `valid + calibrated + new frame` 使用数据，任务3中的 `g_confidenceAccepted` 名称与实际逻辑并不完全一致。

如果面试官追问，可以这样回答：

> 这是当前版本可以继续改进的地方。更严谨的做法是任务层直接使用 `observation.controlUsable`，并对置信度增加进入/退出双阈值和短时保持，既避免误拒绝，也避免低质量观测进入控制环。

主动指出这个问题会比强行辩解更体现代码审查能力。

## 7. 任务3滚球控制：项目最值得讲的部分

### 7.1 任务流程

```text
人工调平 → ARMED → 中心附近且低速 → 运动到+50 mm
       → 连续反向到-50 mm → 位置/速度稳定300 ms → COMPLETE
```

开始条件：

- 摆杆已建立人工零位；
- 视觉数据有效且已标定；
- 球位在中心±12 mm；
- 球速不超过10 mm/s。

完成条件：

- 球位进入-50 mm附近±5 mm；
- 球速不超过10 mm/s；
- 控制器进入HOLD；
- 连续保持300 ms。

### 7.2 为什么不是直接位置PID

只做 `u = Kp × position_error - Kd × velocity` 会有两个问题：

1. 远距离误差很大，P项容易给出过强倾角，导致高速撞向目标。
2. D项在高速阶段可能过早反向，尤其在P项被限幅后，造成错误的加速方向。

因此任务3先根据剩余距离生成参考速度：

```text
v_ref = min(v_max, sqrt(2 × a_brake × remaining_distance))
```

代码使用整数平方根，避免在Cortex-M0+控制周期中引入浮点依赖。

再进行位置项和速度跟踪：

```text
a_cmd = clamp(Kp × position_error)
      + Kd × (v_ref - filtered_velocity)
```

最后把期望加速度换算成摆杆端等效高度：

```text
lift_um = -a_cmd × acceleration_to_lift + compensation
```

正高度使球向负坐标方向加速，所以存在负号。

### 7.3 负向提前反制的根因

实际问题发生在 `+50 mm → -50 mm`：

- 位置P项已经达到限幅；
- 球具有较大负速度；
- 速度D项为了跟踪逐渐降低的参考速度，可能给出正加速度；
- 正加速度对应摆杆向右加速，而此时球距离-50 mm还很远；
- 摆杆提前反向，下一次折返幅度变大，形成逐次放大。

核心修正：当负向运动且剩余距离大于25 mm时：

```text
if move_direction < 0 and remaining > 25 mm:
    acceleration_command = min(acceleration_command, 0)
```

也就是D项可以把驱动逐渐卸载到水平，但不能在远段产生真正的反向加速度。进入最后25 mm后才允许反向制动。

同时对负向路径单独限制：

- 远段加速度上限90 mm/s²；
- 捕获阶段加速度上限40 mm/s²；
- 负向驱动命令上限2200 μm；
- 反向制动最大1200 μm；
- 捕获命令上限1400 μm；
- 每10 ms变化最多100 μm。

### 7.4 边界预测保护

控制器计算：

```text
projected_position = position + velocity × 0.9 s
```

当预测位置将超过±65 mm且仍向外运动时，进入GUARD，施加回收倾角；只有检测到球以一定速度向内运动才解除。

这是独立于正常PD的安全包络。面试时可以强调：安全约束不应该依赖一组“刚好合适”的PID参数。

### 7.5 静摩擦和无进展检测

系统不根据“电机动了没有”判断球是否响应，而是联合检查：

- 当前仍有位置误差；
- 球速低于4 mm/s；
- 450 ms内沿目标方向进展不足2 mm。

满足条件后进入PROBE，按120 μm/100 ms逐渐增加有方向的破静摩擦命令。检测到位移至少3 mm或速度至少8 mm/s后退出，并用指数平均更新该方向的摩擦阈值：

```text
learned = (3 × old + observed) / 4
```

1.8 s仍没有运动则进入STUCK并停止输出，避免电机无限微动。

### 7.6 为什么正负方向分别学习

机械摩擦、重心、曲柄角度和安装误差都可能导致两个方向的起动阈值不同。分别维护 `learnedPositiveUm` 和 `learnedNegativeUm` 比一个统一补偿更合理。

## 8. 任务4—6为什么要与任务3独立

### 8.1 两类工况不同

任务3：

- 目标移动范围大；
- 需要快速运动和折返；
- 允许较强制动；
- 重点是到达指定端点。

任务4—6：

- 车辆本身在运动；
- 目标主要是保持而不是长距离转移；
- 需要低幅、连续和平滑；
- 车辆加速度和俯仰成为主要扰动。

如果直接复用任务3控制器，任务3的轨迹、捕获、GUARD和较强静摩擦探测会使行车保持过于激进。因此代码为任务4—6建立独立状态和参数。

### 8.2 任务4起步前馈

车轮目标从8在1.2 s内逐步升到正常平衡速度24，左右目标按同一比例缩放，保留转向比例。

摆杆同时施加-900 μm起步前馈：

- 前250 ms保持；
- 随后线性衰减；
- 1.2 s时归零。

这体现了前馈和反馈的区别：前馈根据“即将发生的车辆加速”提前补偿，视觉反馈根据“球已经偏了多少”再纠正。

### 8.3 JY61P角度前馈

ARMED阶段记录姿态零点，运行时使用相对角度：

```text
lift_ff = clamp(-Δangle_mdeg × 4.77 μm/mdeg, ±800 μm)
```

4.77 μm/mdeg来自约273.1 mm结构长度的小角度近似。角度输入限制在±12°，前馈输出限制±0.8 mm。

为什么只做前馈，不把IMU作为主反馈？

> 控制目标是球的位置，不是车体角度。IMU只能解释一部分扰动，安装零偏和振动也会影响测量。因此视觉仍是主反馈，IMU失效时只把前馈置零，不能让整个控制停止。

### 8.4 任务5和任务6

- 任务5使用中心0 mm作为保持目标，并在完成一圈后结束。
- 任务6在启动时锁存当时球位作为目标，限制在±100 mm安全范围内，再执行同一保持控制。

这体现了“复用控制器，改变目标生成逻辑”的设计方式。

## 9. 步进电机与摆杆：必须掌握的执行器细节

### 9.1 机械与脉冲换算

- 42型步进电机：200整步/转。
- D36A设置8细分：1600脉冲/转。
- 曲柄等效半径：28.55 mm。
- 圆周长度约179.385 mm。
- 每个微步对应约112 μm端点弧长。

在水平点附近使用小角度近似：

```text
steps ≈ lift_um × 1600 / 179385
```

控制命令通常限制在±3200 μm，对应约±29微步；软件总控制范围±64微步作为更大的安全边界。

### 9.2 非阻塞步进调度

步进脉冲不是用阻塞延时生成，而是：

- 20 kHz定时器ISR运行相位累加器；
- 当前步频累加到20 kHz阈值时产生一个STEP脉冲；
- 10 ms任务更新当前速度、目标速度、加速度和制动距离。

这样主循环仍能解析视觉、刷新状态机和控制车轮。

### 9.3 加减速与换向

换向时先把当前步频降到0，再切DIR，避免高速瞬间反转。制动距离使用：

```text
braking_steps = speed² / (2 × acceleration)
```

剩余步数进入制动距离后开始降速。

### 9.4 无限位开关的风险

最终样机没有物理限位，也没有绝对位置传感器。固件把人工调平位置定义为逻辑中心，并只在局部软范围内运动。

这个方案的弱点必须主动承认：

- 断电后位置丢失；
- 步进丢步后软件位置与机械位置不一致；
- 多次重复实验需要重新调平；
- 软限位不能防止初始零位错误。

更好的工程版本应增加限位开关、磁编码器或绝对角度传感器，并在启动时自动回零。

## 10. 嵌入式实时性与并发

### 10.1 为什么没有使用RTOS

系统任务数量有限，周期关系明确，使用1 ms时基和协作式分频调度可以降低内存和上下文切换开销，也方便比赛现场调试。

### 10.2 ISR中做什么

- SysTick：增加毫秒计数、采样灰度、按键去抖、可选限位去抖。
- UART ISR：搬运字节到环形缓冲区。
- 编码器GPIO ISR：累计边沿。
- STEP Timer ISR：生成脉冲并更新逻辑步数。

### 10.3 主循环中做什么

- 视觉/JY61P协议解析；
- 任务状态机；
- 巡线、轮速和滚球控制；
- OLED显示；
- 故障转移。

### 10.4 共享变量如何保护

步进位置、环形缓冲区首尾指针等由ISR和主循环共享。代码使用 `volatile` 保证每次读取真实内存，并在需要一致快照时短暂保存PRIMASK、关闭中断、完成读写后恢复中断。

注意：`volatile`不能替代原子性，也不能解决所有竞态；它只解决编译器优化可见性。

### 10.5 当前调度的不足

- 主循环是协作式的，任何长耗时函数都会给其他任务增加抖动。
- 没有记录最坏执行时间WCET和任务超期次数。
- OLED/I²C如果阻塞过久，可能影响协议处理。

后续可以增加运行时间统计、deadline miss计数，或把显示等低优先级任务进一步切片。

## 12. 调试方法：面试官更看重你怎么解决问题

### 12.1 正确的联调顺序

1. 断开执行器，确认供电、共地和逻辑电平。
2. 单独验证左右轮方向和编码器符号。
3. 验证八路灰度物理顺序与误差正负号。
4. 调平摆杆，低速确认DIR=0抬高右端、DIR=1降低右端。
5. 只看UART统计，确认字节、帧头、CRC、序号和超时。
6. 在-50、0、+50 mm检查视觉坐标标定。
7. 先运行单个控制环，再做车轮和滚球协同。
8. 每次只修改一组参数，并保存CSV和版本。

### 12.2 如何区分PID问题和驱动问题

如果电机“卡卡的”，按以下顺序排查：

- 空载STEP脉冲是否均匀；
- D36A细分、电流和使能电平是否正确；
- 步频是否超过当前负载的起动能力；
- 加速度是否过大；
- 电源是否掉压；
- 机械是否卡滞；
- 最后才看控制器是否频繁反向命令。

如果固定方向、固定步频仍不平滑，优先怀疑驱动/机械；如果只有闭环时来回抖，才重点检查控制参数、噪声和死区。

### 12.3 为什么采集CSV

只靠肉眼容易把“位置超调”“速度估计跳变”“执行器饱和”和“通信丢帧”混为一谈。CSV至少应包含：

- 时间戳；
- 球位、球速；
- 目标位置、参考速度；
- 控制阶段；
- 摆杆命令与实际逻辑位置；
- 视觉序号、有效位和置信度；
- 保护状态。

用多次重复实验比较峰值位置、第一次回弹位置、稳定时间和失败模式，比“感觉更稳”更有说服力。

### 13.1 灰度中心

D4和D5激活：

```text
(4000 + 5000) / 2 - 4500 = 0
```

### 13.2 步进分辨率


```text
h ≈ L × θ
1 mdeg = π / 180000 rad

```

## 14. 高频面试问题与参考回答

### Q1：为什么巡线用PD，不用PID？

巡线目标是快速抑制横向误差，系统本身不存在必须通过积分消除的固定稳态偏差；积分容易在弯道和饱和时累积。P提供转向，D抑制误差变化，左右轮速度差由内层PI准确执行。

### Q2：为什么轮速用PI？

电机存在摩擦、电池电压和左右差异，仅靠固定PWM会有稳态速度误差。PI能消除误差，前馈缩短响应时间，条件积分防止饱和积累。

### Q3：为什么滚球不用一个PID解决？

因为存在长距离运动、目标折返、视觉延迟、静摩擦、执行器限幅和安全边界。连续PD只适合局部控制，轨迹规划和状态机负责不同阶段与约束。

### Q4：D项为什么会让任务3提前反向？

P项被限幅后不再随距离增加，而D项与速度误差有关。球负向速度较大、参考速度开始下降时，D项可能超过P项，使合成加速度变正，摆杆在远离目标时就反向。解决方案是在负向远段禁止正加速度，只允许D卸载到0。

### Q5：如何处理视觉延迟？

使用球速反馈、测量年龄、帧序号和陈旧超时；轨迹规划还用速度乘执行器滞后时间扣除有效剩余距离，边界保护使用前向位置预测。

### Q6：为什么使用整数运算？

MSPM0G3507是Cortex-M0+，固定点整数能降低计算和库依赖，时序更可控。代价是必须明确单位和缩放，注意乘法溢出与舍入。

### Q7：环形缓冲区为什么是256字节？

2的幂可以使用按位与实现回绕；容量约等于9帧视觉数据，能够吸收短时主循环抖动。满时丢弃新字节并统计overflow，而不是覆盖未读数据。

### Q8：为什么JY61P不用来直接闭环控制摆杆？

目标是球位，角度只是扰动信息。IMU存在安装零偏和振动，因此只做限幅前馈；视觉闭环才决定最终球位。IMU失效时系统仍可降级运行。

### Q9：没有限位开关怎么保证安全？

人工调平建立逻辑零位，DIR方向已验证，目标步数和控制范围双重限幅，急停能立即停止并禁用驱动。但这只能降低风险，不能替代物理限位；丢步或零位错误仍是当前方案的弱点。

### Q10：步进电机为什么会丢步？

起动频率/加速度过高、负载过大、电流不足、供电掉压、机械卡滞或高速反转都可能造成丢步。当前方案采用加减速、换向先降速和较低最大步频，但没有闭环位置反馈，无法检测所有丢步。

### Q11：为什么任务3和任务4—6要分开？

任务3是大范围轨迹和折返，任务4—6是运动平台上的小范围保持。两者对增益、限幅、静摩擦补偿和状态转换要求不同，复用同一状态会互相污染。

### Q12：如何证明系统实时？

目前能说明任务周期和ISR职责清晰，但没有完整WCET测量，因此不能声称做过严格实时证明。下一步应使用GPIO翻转或周期计数器测量最坏执行时间、抖动和deadline miss。

### Q13：为什么不用RTOS？

任务数量有限、周期固定，协作调度更轻量。但当功能继续增加、通信和日志复杂后，RTOS能提供更清晰的优先级、队列和超时管理。

### Q14：如何避免积分饱和？

轮速PI使用条件积分：输出未饱和或误差方向能帮助退出饱和时才更新积分，同时积分本身也限幅。

### Q15：如果视觉突然丢球怎么办？

先把摆杆目标回到水平，不继续使用旧球位；短时等待恢复，超过任务对应阈值后进入视觉故障并停止任务。协议层还会在120 ms后将观测标记为陈旧。

### Q16：项目里你做过最有价值的调试是什么？

推荐回答负向提前反制问题：从现象“回弹逐次增大”分析到P限幅后D项符号反转，再通过分段约束让远段只卸载不反向，体现了从数据、符号和物理方向推导根因，而不是盲目降低增益。

### Q17：如果重新做一次，你会改什么？

增加绝对角度/位置反馈和物理限位；记录完整时序日志；建立HIL/协议单元测试；统一SafetyManager；让任务层真正使用 `controlUsable`；测量WCET；为视觉端也公开可复现代码和标定工具。

### Q18：这个项目最大的工程风险是什么？

开环步进的位置可信度。控制器虽然闭环观察球位，但执行器逻辑零位仍可能因丢步漂移，导致相同命令对应不同机械倾角，破坏重复性和软限位可信度。

### Q19：怎么确认控制方向没有写反？

分三步：固定DIR低速观察摆杆右端；人工轻微抬高右端观察球运动方向；检查视觉坐标正负。只有执行器方向、球物理方向和视觉坐标三者一致后才允许闭环。

### Q20：代码里还有哪些不足？

除了无绝对位置反馈，还包括视觉置信度使用不够统一、集中安全管理尚未完成、硬件在环和单元测试不足、部分参数来自实车经验而非系统辨识、公开仓库暂未包含视觉端模型和代码。
