# H 题巡线、按键与 OLED 联调说明

## 本阶段范围

本固件完成任务 2、4、5、6 共用的底盘巡线、任务选择、比赛计时和停车判定。
任务 5、6 的滚球视觉、摆杆回零和滚球闭环仍是下一阶段内容；当前代码不会使能两路 D36A。

旧工程只复用了已验证的电机极性、编码器中断、八路传感器顺序、轮速 PI 初值和
SSD1306 I2C 底层。旧工程的逆时针直角正方形识别、原地转向和四角计数均未移植。

## 按键

四个按键均为低电平按下，内部上拉，软件消抖 15 ms。

| 按键 | 引脚 | 功能 |
|---|---|---|
| KEY1 | PB2 | ARMED 状态启动；RUN 状态台架暂停/继续 |
| KEY2 | PB3 | 非运行状态按 2 → 4 → 5 → 6 循环选择任务 |
| KEY3 | PB23 | SELECT 状态确认；ARMED 状态也可执行启动 |
| KEY4 | PB15 | 立即急停；在 ESTOP 状态再次按下回到 SELECT |

正式比赛建议采用：KEY2 选任务 → KEY3 确认 → 车头朝 A→B 顺时针方向放置 →
KEY1 启动。OLED 第一行固定显示 `H TASK n CW`，用于提醒顺时针朝向。

## 各任务停车逻辑

- 任务 2：从 A 启动，离开 A 横线后连续巡线；满足最小时间、最小里程并再次稳定
  检测 A 横线时停车，20 s 超时。
- 任务 4：从 A 启动，编码器平均里程达到 1.55 m 时停车，确保已经通过 B；8 s 超时。
- 任务 5、6：巡线停车逻辑相同，重新检测 A 横线时停车，30 s 超时。
- A 横线判定为至少 6/8 路同时检测黑色，并要求连续 30 ms。
- 启动后必须连续 50 ms 不在横线上，才允许后续把横线当作终点。
- 丢线时短时按上一次误差方向搜索；连续 400 ms 丢线进入 `LINE ERR` 并停机。

任务 2、5、6 的里程门限不是主要终点，只用于排除中途宽黑斑误触发；真正终点是 A 横线。

## OLED

128×64 OLED 分四页刷新：

1. `H TASK n CW`
2. `STATE SELECT/ARMED/RUN/PAUSE/DONE/TIMEOUT/LINE ERR/ESTOP`
3. `TIME sss.ssS`
4. `D xxxx E xxxx`（里程 mm、巡线误差）

OLED 离线或 I2C 超时不会阻塞底盘控制。

## 首次上车必须标定

1. 悬空车轮，确认正目标速度时左右轮都向车辆前方转。
2. 手动遮挡 D1 到 D8，确认 D1 是车辆左侧最外传感器；若物理排线相反，将
   `H_LINE_SENSOR_REVERSED` 改为 1。
3. 让车沿 1.000 m 直线低速行驶，记录左右编码器边沿平均值，将其写入
   `H_ENCODER_EDGES_PER_METER`。当前 `7600` 只是 MG513X 的初始估算值。
4. 用任务 4 验证 1.55 m 停车点；按车辆传感器到车体基准点的安装偏移微调
   `H_AB_STOP_DISTANCE_MM`。
5. 在完整赛道低速跑一圈，确认 A 横线能产生至少 6 路同时有效；否则调整
   `H_MARKER_MIN_ACTIVE`，不要先降低到 4 以下。
6. 最后逐步调整 `H_TASK2_BASE_SPEED`、`H_BALANCE_BASE_SPEED` 和轮速 PI。

主要参数在 `config/control_config.h` 和 `config/hardware_config.h`。

## CCS 构建注意

不要复用从其他 CCS 工作区复制来的 `Debug` 目录。将本工程重新导入 CCS 后执行
Clean Project / Build Project，让 CCS 依据当前工程位置重新生成 makefile 和
`ti_msp_dl_config.*`。`system.syscfg` 是引脚配置的唯一源文件。
